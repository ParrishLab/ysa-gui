# PyUpdater Setup Guide

This document describes how to set up PyUpdater for the YSA GUI auto-update system.

## Prerequisites

PyUpdater is already added to `src/helpers/update/requirements.txt`. Install it:

```bash
pip install -r src/helpers/update/requirements.txt
```

## One-Time Setup

### 1. Generate Signing Keys

PyUpdater uses ed25519 signatures to verify updates. Generate your keys:

```bash
pyupdater keys -c
```

This creates a `.pyupdater/` directory with:
- `keypack.pyu` - Your private keys (keep secret, add to `.gitignore`)
- Public key (will be shown in next step)

**IMPORTANT**: Add `.pyupdater/` to `.gitignore` if not already present!

### 2. Get Your Public Key

```bash
pyupdater keys --show
```

Copy the public key string (it looks like a long base64 string).

### 3. Add Public Key to Code

Edit `src/helpers/update/Updater.py` and set the public key:

```python
CLIENT_CONFIG = {
    "APP_NAME": APP_NAME,
    "COMPANY_NAME": COMPANY_NAME,
    "UPDATE_URLS": UPDATE_URLS,
    "PUBLIC_KEY": "your_public_key_here",  # Paste the key from step 2
}
```

### 4. Initialize PyUpdater Config

```bash
pyupdater init
```

Follow the prompts:
- **App name**: `YsaGUI`
- **Company name**: `ParrishLab`
- **Update URLs**: `https://github.com/ParrishLab/ysa-gui/releases/download/latest/`
- **Plugins**: Skip for now (press Enter)

This creates a `.pyupdater/config.pyu` file with your settings.

### 5. Test Local Build

Build your app with PyInstaller as usual:

```bash
pyinstaller main.spec
```

Then package it with PyUpdater:

```bash
# macOS
pyupdater pkg --process dist/YsaGUI.app --app-version 1.0.0

# Windows
pyupdater pkg --process dist/YsaGUI --app-version 1.0.0
```

Sign the package:

```bash
pyupdater pkg --sign
```

## CI/CD Integration

The CI/CD pipeline needs to be updated to use PyUpdater. See the next section for details.

## Architecture Overview

### How PyUpdater Works

1. **Client Side** (User's machine):
   - App checks for updates using `check_for_update()`
   - Downloads update manifest from `UPDATE_URLS`
   - Verifies signature using `PUBLIC_KEY`
   - If update available, downloads only changed files (delta updates)
   - Extracts update and restarts the app

2. **Server Side** (GitHub Releases):
   - CI/CD builds the app with PyInstaller
   - Packages it with `pyupdater pkg --process`
   - Signs it with `pyupdater pkg --sign` (uses private key from `.pyupdater/`)
   - Uploads to GitHub releases with `pyupdater upload`

### File Structure

```
ysa-gui/
├── .pyupdater/              # PyUpdater config and keys (gitignored)
│   ├── config.pyu           # Configuration file
│   └── keypack.pyu          # Private keys (KEEP SECRET!)
├── pyu-data/                # Generated by PyUpdater (can be gitignored)
│   ├── new/                 # Newly processed packages
│   ├── deploy/              # Ready-to-upload packages
│   └── files/               # Version manifest files
└── src/helpers/update/
    └── Updater.py           # Client-side updater code
```

## Testing Updates Locally

### 1. Create a Test Version

Build version 1.0.0:
```bash
pyinstaller main.spec
pyupdater pkg --process dist/YsaGUI.app --app-version 1.0.0
pyupdater pkg --sign
```

### 2. Serve Updates Locally

```bash
cd pyu-data/deploy
python -m http.server 8000
```

### 3. Update the Client

Edit `Updater.py` temporarily to use your local server:
```python
UPDATE_URLS = ["http://localhost:8000/"]
```

### 4. Test the Update Flow

Run the app with version 1.0.0, then:
- Build version 1.0.1
- Process and sign with PyUpdater
- The running app should detect the new version
- Click "Yes" to download and install

## Troubleshooting

### "No update available" when one should exist

- Check that `PUBLIC_KEY` is set correctly in `Updater.py`
- Verify the update manifest is accessible at `UPDATE_URLS[0]/versions.gz`
- Check the version number in `src/helpers/Constants.py`

### "Signature verification failed"

- Public key in `Updater.py` doesn't match the private key used to sign
- Re-run `pyupdater keys --show` and update `Updater.py`

### "Failed to extract and restart"

- Check file permissions on the extracted update
- On macOS, you may need to re-sign the app after extraction
- Check console logs for more details

## Security Best Practices

1. **Keep private keys secret**: Never commit `.pyupdater/keypack.pyu` to git
2. **Use GitHub Secrets**: Store the keypack in CI/CD secrets
3. **Verify signatures**: Always use signature verification in production
4. **Use HTTPS**: Never use HTTP for `UPDATE_URLS` in production
5. **Test thoroughly**: Always test updates on a staging environment first
